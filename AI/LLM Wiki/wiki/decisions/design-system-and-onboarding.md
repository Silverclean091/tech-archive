# 디자인 시스템 및 온보딩 플로우 결정

## 결정 사항

### 디자인 시스템 (Flow UI)
- **명칭**: Flow UI
- **범위**: 색상, 타이포그래피, 컴포넌트 가이드 포함
- **원칙**: 리스트뷰 중심의 저밀도 레이아웃
- **의의**: 회사 최초의 자체 디자인 시스템 구축

### 온보딩 플로우
- **단계**: 3단계로 축소 (기존 5단계 → 3단계)
  1. 회원가입 + 팀생성 통합
  2. 팀원 초대
  3. 첫 할일 등록
- **튜토리얼**: 선택적 스킵 가능하도록 변경
- **배경**: 기존 5단계 온보딩이 높은 이탈률 야기 가능성

### 다크모드
- **MVP(v1.0) 범위**: 제외
- **예정 버전**: v1.1에 포함 (디자인 리소스 부족으로 인한 미연기)

## 배경
와이어프레임 리뷰 결과 높은 정보 밀도 문제 지적 → 단순화 방향으로 전환

## 의사결정 과정
1. 디자인 시스템 명칭: "Flow UI" vs "TaskKit" 논의 → 프로젝트 일관성으로 Flow UI 선정
2. 온보딩: 기존 5단계 vs 3단계 논의 → 이탈률 우려로 3단계 축소 결정
3. 다크모드: MVP 포함 vs 제외 논의 → 리소스 부족으로 v1.1 연기
