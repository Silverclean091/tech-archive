## 안건
1. 프로젝트 배경 및 목표 공유
2. 타겟 사용자 및 MVP 범위 정의
3. 기술 스택 확정
4. 역할 분담 및 커뮤니케이션 규칙

## 논의 내용

### 1. 프로젝트 배경
회사 내부적으로 여러 협업 툴을 혼용하면서 업무 효율이 떨어진다는 문제 제기가 지속되어, 자체 업무관리 모바일 앱 "TaskFlow"를 신규 개발하기로 함. 기존 외주 협업 툴 대비 알림/캘린더 동기화 기능을 강화하는 방향으로 차별화.

### 2. 타겟 사용자
1차 타겟은 스타트업/중소규모 팀의 실무자로 정의. 특히 하루 평균 5개 이상 프로젝트를 동시에 관리하는 사용자를 "파워유저"로 지칭하기로 함. 파워유저 그룹의 피드백을 베타 테스트 우선순위에 반영하기로 함.

### 3. MVP 범위 논의
초기에는 할일관리, 팀 캘린더 동기화, 협업 코멘트, 알림 4개 기능만 포함하자는 의견과, 파일 공유까지 포함하자는 의견이 대립. 논의 결과 파일 공유는 2차 버전으로 미루기로 함.

### 4. 기술 스택
크로스플랫폼 개발 속도를 고려해 React Native를 채택하자는 제안이 있었고, 백엔드는 기존 사내 인프라와의 호환성을 위해 Node.js + PostgreSQL로 진행하자는 의견에 이견 없음.

## 결정 사항
- MVP 범위는 할일관리, 팀 캘린더 동기화, 협업 코멘트, 알림 4개 기능으로 한정한다. 파일 공유 기능은 2차 버전(v2)으로 연기한다.
- 타겟 플랫폼은 iOS/Android 동시 출시로 확정한다.
- 기술 스택은 프론트엔드 React Native, 백엔드 Node.js + PostgreSQL로 확정한다.
- 프로젝트 전체 일정은 별도 로드맵 문서로 관리하며, PM(김도윤)이 매주 진행 상황을 공유한다.
- 주간 정기 회의는 매주 목요일 10시로 고정한다.

## 용어 정의
- **파워유저(Power User)**: 하루 평균 5개 이상의 프로젝트를 동시에 관리하는 TaskFlow 핵심 타겟 사용자군. 베타 테스트 및 기능 우선순위 결정 시 우선 참고 대상.
- **MVP(Minimum Viable Product)**: 본 프로젝트에서는 할일관리, 팀 캘린더 동기화, 협업 코멘트, 알림 4개 기능만을 포함하는 최소 출시 버전을 의미함.
